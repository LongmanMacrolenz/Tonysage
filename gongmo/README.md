# 정책공모 작업실

정부·지자체·공공기관의 정책 제안 공모를 모아 보고, 공모 하나를 골라 Claude와 대화하며 제안서를 쓰는 페이지입니다.

정부 서비스가 아닙니다. 공고 내용은 확인일 기준으로 정리한 것이므로 응모 전에 공식 공고를 다시 확인해야 합니다.

## 화면

- **목록**: 접수 중, 상시 창구, 해마다 열리는 공모, 내 작업으로 나눠 봅니다. 마감 가까운 순이나 상금 큰 순으로 정렬하고 주제·주최·상금·팀 참가로 거릅니다.
- **공고 한 장**: 참여 조건, 참가 형태, 상금, 접수 기간, 공모 내용, 제출물, 제출 방법, 심사, 발표, 생성형 AI 규정, 문의를 같은 순서로 보여 줍니다. 공고에 없는 항목은 '공식 공고에서 확인'으로 표시합니다.
- **제출 패키지**: 공모마다 네 단계로 진행합니다.
  1. 내가 할 일: 정책 방향과 아이디어 초안을 적습니다.
  2. Claude가 할 일: 제안서 본문을 쓰고, 심사위원 관점으로 검토해 다시 쓴 뒤, 1쪽 요약·참가신청서 기재 초안·온라인 접수 입력란·이메일 문안·제출 파일 목록·확인할 사실·생성형 AI 활용 고지를 만듭니다.
  3. 결과를 고치고 전체 패키지(.zip)나 제안서·1쪽 요약·패키지 안내서(.docx)로 내려받습니다. [이름], [확인 필요: …] 같은 빈칸은 문서에서 노란색으로 표시됩니다.
  4. 내가 할 일: 제출처에 로그인해 업로드하거나 이메일을 보내고 '제출을 마쳤어요'를 누릅니다.
- **내 조건과 참여 자격**: 머리글의 '내 조건'에 사는 곳, 직장·학교 소재지, 출생 연도, 신분(대학(원)생 등)을 넣으면 공모마다 참여 자격을 판정합니다. 판정은 '참여 가능', '자격 확인 필요', '참여 불가' 세 가지이고, 이유를 공고 한 장 맨 위에 보여 줍니다. '참여 가능한 것만'이 켜져 있으면 참여 불가 공모는 목록과 홈 집계에서 빠지고, 참여 불가 공모에서 작업을 시작하거나 패키지를 만들려 하면 먼저 경고합니다. 게시된 페이지에서는 이 정보가 본인만 읽을 수 있는 저장 공간에 저장됩니다.
- **AI 엔진**: 머리글에서 Opus 5.5, Fable 5.1, 자동(기본 모델) 가운데 고르고 생각 수준을 낮음·보통·높음으로 정합니다. 대화, 칸별 초안, 패키지 만들기, 공고 정리에 모두 적용됩니다. 고른 모델을 계정에서 쓸 수 없으면 기본 모델이 답하고 화면에 알려 줍니다. 페이지 안의 Claude는 웹 검색을 하지 않습니다.
- **Claude와 대화**: 공고 한 장의 내용과 (선택하면) 내 제안서 초안이 Claude에게 함께 전달됩니다. 참여 자격 점검, 아이디어 5개, 근거 자료 찾을 곳, 심사위원처럼 검토 같은 시작 버튼이 있습니다. 답변은 버튼 하나로 제안서 칸에 붙입니다.
- **제안서**: 제목, 한 줄 요약, 현황 및 문제점, 개선 방안, 기대 효과, 실행 방안, 근거 자료 칸이 있습니다. 칸마다 Claude 초안이나 다듬기를 받아 바꾸거나 뒤에 붙입니다. 아래에 공고에서 뽑은 제출 전 점검표가 있습니다.
- **공고 추가**: 공고문을 붙여 넣으면 Claude가 항목을 정리하고, 확인한 뒤 목록에 넣습니다.

## 여러 사람이 함께 쓰기

claude.ai의 공유 메뉴로 다른 사람을 초대하면 같은 페이지를 씁니다. 공고 목록은 함께 보고, 초안과 대화는 사람마다 따로 둡니다.

| 무엇 | 어디에 | 누가 읽고 쓰나 |
| --- | --- | --- |
| 공고 목록(`contests`) | 페이지 저장소 | 모두 읽음. 소유자와 편집자만 추가·삭제. 다른 사람이 추가한 공고는 그 사람 브라우저에만 남음 |
| 소유자의 초안·대화(`projects`, `chats`) | 페이지 저장소 | 소유자만 |
| 다른 사람의 초안·대화 | `data/users/<id>/work/projects`, `…/chats` | 본인만. 저장소에 쓸 수 없는 사람(보기 권한, 조직 밖 사용자)은 그 브라우저에 저장 |
| 내 조건 | `data/users/<id>/profile` | 본인만. 쓸 수 없으면 그 브라우저에 저장 |

페이지 안의 Claude는 그 페이지를 쓰는 사람의 Claude 계정 사용량을 씁니다. 처음 부를 때 허용할지 묻습니다.

## Claude와 쓰는 방식

claude.ai에 게시한 페이지에서는 페이지 안에서 바로 Claude에게 묻고, 대화와 초안을 그 페이지의 저장소에 저장합니다. 소유자의 초안은 Claude Code 세션에서도 읽고 이어서 도울 수 있습니다.

브라우저에서 `index.html`을 그냥 열면 Claude를 직접 부를 수 없습니다. 이때는 '대화용 요약 복사'로 공고 요약, 대화 원칙, 내 초안을 한 번에 복사해 Claude 대화창에 붙여 넣습니다. 초안은 그 브라우저에만 저장됩니다.

페이지 안의 Claude에게는 다음 원칙을 함께 보냅니다.

1. 공모 조건은 공고 요약에 있는 사실만 말하고, 없는 내용은 공식 공고 확인을 권합니다.
2. 인터넷을 볼 수 없으므로 통계·법령·예산 수치는 지어내지 않고 [확인 필요]와 확인할 공식 출처를 붙입니다.
3. 공고에 생성형 AI 규정이 있으면 먼저 알려 주고, 제출하는 글은 사용자가 자기 말로 고쳐 쓰도록 돕습니다.

## 데이터

`contests.json`에 공모 63건과 모음 사이트 14곳이 있습니다(2026-11-05 기준).

| 구분 | 건수 | 설명 |
| --- | --- | --- |
| 접수 중·예정 | 39 | 2026년 11월~2027년 1월 마감 공모. 6건은 공식 공고를 열지 못해 '공식 공고 미확인' |
| 해마다 열림 | 4 | 국민생각함 정책 아이디어 공모전 등. 2026년 일정 기준 |
| 상시 창구 | 20 | 국민신문고 국민제안, 국민참여예산, 국회 국민동의청원, 복권기금 아이디어 공모(상시 접수), 성동구 상상하우스 등 |

각 공모의 `elig`는 참여 자격입니다: `regions`(거주지 제한, 시·도 정식 명칭과 시·군·구), `workSchoolOk`(그 지역 직장·학교도 허용), `soft`(제한이 확실하지 않아 '확인 필요'로만 표시), `minAge`·`maxAge`, `statuses`(예: 대학(원)생), `extra`(자동 판정이 어려운 조건), `unknown`(자격 미확인), `own`(내 지역 창구), `note`(사람이 읽는 요약).

각 공모는 같은 항목을 가집니다: `who`(참여 조건), `team`(참가 형태), `limit`(응모 제한), `prize`(`kind`, `top`, `total`, `text`), `start`·`end`·`endTime`(기간), `theme`(공모 내용), `submit`(제출물), `how`(제출 방법), `judging`(심사), `announce`(발표), `aiRule`(생성형 AI 규정), `contact`, `url`, `verified`, `source`, `checkedAt`.

게시된 페이지는 `contests.json`을 기본 목록으로 쓰고, 페이지 저장소의 `contests` 모음에 있는 문서로 덮어씁니다. 그래서 새 공모는 다시 게시하지 않고도 저장소에 문서를 넣어 추가할 수 있습니다. 같은 id 문서에 `hidden: true`를 넣으면 목록에서 빠집니다.

## 파일

| 파일 | 내용 |
| --- | --- |
| `page.html` | 화면, 스타일, 동작. `__SNAPSHOT__` 자리에 데이터가 들어감 |
| `contests.json` | 공모 목록 |
| `build.py` | 데이터를 넣어 `index.html`(브라우저용)이나 게시용 파일을 만듦 |
| `index.html` | 만들어진 페이지. 직접 고치지 않음 |
| `tests/data.test.mjs` | 공모 데이터 형식 점검 |

Word 문서는 `docx` 9.5.1(jsDelivr)로, 묶음 파일은 JSZip 3.10.1(cdnjs)로 브라우저 안에서 만듭니다. 두 라이브러리는 페이지를 열 때 백그라운드로 불러오며, 불러오지 못하면 복사 버튼으로 대신합니다.

## 만들기와 점검

```sh
node gongmo/tests/data.test.mjs
python3 gongmo/build.py
python3 gongmo/build.py --artifact /tmp/gongmo.html
```

## 목록 갱신

1. 마감이 지난 공모는 화면에서 자동으로 '마감'이 되고 '접수 중' 목록에서 빠집니다.
2. 새 공모는 `contests.json`에 같은 항목으로 넣고 `verified`와 `source`를 정확히 적습니다. 공식 공고를 열어 보지 못했으면 `verified: false`로 둡니다.
3. 해마다 열리는 공모는 새 회차 공고가 나오면 날짜와 시상을 그 회차로 바꿉니다.
